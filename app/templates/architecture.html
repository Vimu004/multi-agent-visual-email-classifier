Request Journey

  1. User submits the account-access email.
  2. Classification Agent identifies account_access.
  3. Supervisor selects the Account Access Agent.
  4. Specialist reads the local account policy JSON.
  5. Response Agent drafts a secure reply.
  6. Reviewer flags the identity change as sensitive.
  7. Workflow pauses and persists in SQLite.
  8. Human approves via the dashboard.
  9. Final response is stored and shown.

Human-in-the-loop

The LangGraph approval gate pauses execution when classifier confidence is low, when specialists raise a high-risk flag, or when the reviewer requests human input. The current state and trace are stored in SQLite so the presenter can resume or reject from the dashboard. Account changes, refunds, deletions, and any schema validation issues always require approval.
