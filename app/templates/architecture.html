System Architecture

Two pipelines, one shared inbox — an agentic baseline and a supervisor-led multi-agentic system built on langgraph-supervisor.

Mode A — Agentic (single agent)

One agent, one Think → Act → Observe pass. Classify, then forward. No risk check, no department decision, no human-in-the-loop.

Mode B — Multi-Agentic (supervisor + department agents)

A real langgraph-supervisor supervisor hands the email to exactly one department agent, which analyzes it and decides an action — then response, review, and a human-approval gate. Drawn as the supervisor hub it actually is.

Department agent (LLM decision) High-risk agent (usually pauses for approval) Deterministic node Human-in-the-loop

Request Journey (multi-agentic, billing example)

  1. Customer submits a billing email with a duplicate-charge complaint.
  2. Classification Agent identifies billing_support.
  3. Supervisor hands off to the Billing Support Agent via a real langgraph-supervisor tool call.
  4. Billing agent reads the local billing policy JSON and decides an action — e.g. escalate for a refund over the auto-approve threshold.
  5. Billing agent hands back to the supervisor.
  6. Response Agent drafts a reply referencing that decision.
  7. Reviewer flags the refund as sensitive.
  8. Workflow pauses and persists in SQLite.
  9. Human approves or edits the draft from the inbox UI.
  10. Final response is stored and shown.

Human-in-the-loop (multi-agentic only)

The approval gate pauses execution when classifier confidence is low, when a department agent's decision is high-risk, or when the reviewer requests human input. State and trace are stored in SQLite so the presenter can resume or reject from the inbox UI. Refunds, account/identity changes, and chargeback threats always require approval — the agentic mode has no equivalent check at all, which is the point of contrast between the two modes.
